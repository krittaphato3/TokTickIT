## 3. Reflection on Specification-Agent Use

Contract-first worked. The spec agent forced frozen numbering (FR/BR/AC/AD), which made traceability mechanical: every API endpoint and every planned test points back to a numbered requirement. The three load-bearing decisions were AD-01 (opaque session cookie `toktickit.sid` with server-side sessions, sliding plus absolute expiry, and CSRF double-submit — chosen over stateless JWT for immediate logout invalidation), AD-02 (Administrator is view-only on the staff ticket surface; staff mutations are IT Staff only), and AD-03 (any active role may create tickets as requester-self through one server-derived identity path). The appears-resolved versus formal-resolve distinction (BR-05) and the AD-06 IT Priority copy-on-claim rule only became crisp because the agent had to write them as testable rules rather than prose. The cost was iteration: three alignment passes were needed to keep the four docs consistent.

## 4. Reflection on Coding-Agent Use

The coding agent has not been used for application code in this increment. All AI output so far is documentation-only: the engineering contract, this use record, and the reviewer scaffold. Implementation (migration, auth, queue/detail, admin screen, tests) remains pending and will be gated on contract approval. This separation was deliberate — it kept the contract from being reverse-written from generated code and preserves the Spec DD requirement that the specification exist before the main implementation PRs. When coding begins, the agent will be constrained to the frozen contract and the Definition of Done, with any deviation treated as a versioned contract amendment.

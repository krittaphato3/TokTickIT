## My Reflection

The AI coding agent significantly accelerated the implementation of Issue 2's database schema. What would have been tedious manual schema design was condensed into a single prompt-response cycle where I provided the Lab 2 specification and the AI generated the complete Prisma schema and migration SQL. The AI was particularly effective at generating the raw SQL migration with correct enum types, foreign key constraints, and indexes.

However, I retained full responsibility for the data model. I corrected the ticketNumber column type to VARCHAR(20) to match the TTK-YYYY-000000 format, verified that Cascade deletes were only applied where appropriate (Attachment), and ensured Restrict was used for requesterId, categoryId, and systemId to prevent accidental data loss. I also added the ON CONFLICT clauses to the seed inserts to make the migration idempotent.

In conclusion, the AI served as an efficient schema generator, but the final schema reflects my judgment about referential integrity, naming conventions, and seed idempotency. Every model, enum, and index was reviewed against the Lab 2 specification to ensure correctness.

For Issue 3 (Development Requester context and selector), the AI accelerated turning the API and UI specs into working code and tests. I kept responsibility for the data-access contract (only active requesters, BR-15), the required selector caption (BR-03), and confirming that the full test suite, lint, and build stayed green after the refactor. The AI was especially useful for splitting the context into files to respect React Fast Refresh rules and for adapting the Lab 1 test stubs to URL-routed mocks once the app began loading requesters on mount.

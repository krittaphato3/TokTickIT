# AI Use and Reflection

LLM used: Antigravity / Gemini 3.8 Flash Medium (thought level: high)

| Prompt Name | Actual Prompt Text | My Reflection |
|---|---|---|
| Contract Spec Agent | Write the Sprint 4 engineering contract (specification, tests, ui-spec, api-spec, reviewer) from the handout digest and my default decisions; Lab 3 behavior is the base; every AC must map to a planned test. | Using the LLM to draft the specification and traceability matrix upfront established strict architectural guardrails. It forced me to think deeply about system edge cases, schema rollback plans, and exact error responses before touching any production code. |
| Actions Taken Foundation | Write failing API and migration tests first, then implement the ActionTaken schema, data-preserving migration, rollback SQL, idempotent seed and Actions Taken API per the contract. | Directing the AI under strict test-driven development prevented unnecessary scope creep. Witnessing the API tests fail first confirmed that the data-preserving migration and rollback scripts were genuinely protecting historical Lab 3 data. |
| Ticket Workflow | Implement a single server-side transition matrix, the resolution gate, and expectedVersion conflict handling with API, unit, UI and E2E tests; the backend must reject UI-bypassing calls. | The AI effectively generated the 8x8 transition truth table and optimistic concurrency versioning. However, human review was crucial to verify that the resolution gate could not be bypassed by direct API calls and that 409 conflict reload states behaved gracefully. |
| Actions Taken UI | Add the Actions Taken area to Ticket Detail (staff create/edit, requester read-only) per ui-spec.md with validation, busy state, duplicate-submit protection and data preserved after failure. | The AI rapidly structured responsive desktop table and mobile card layouts following our Zen Green palette. I had to guide the assistant specifically on idempotent submission protection to ensure network failures never wiped user-entered form drafts. |
| Dashboards | Implement backend-computed Requester and Staff dashboards with drill-down links and tests comparing every metric to independent DB queries. | The prompt ensured all aggregation metrics were computed efficiently on the server via Prisma instead of dumping full collections to the browser. Comparing metrics against independent database queries verified metric accuracy and role-based data isolation. |
| Final Hardening | Run an authorization sweep, axe accessibility, responsive and console-error checks and Labs 1-3 regression; fix findings; finalize README and tests.md from real results. | Pairing Playwright with `@axe-core/playwright` across multiple viewports proved invaluable for catching accessibility and focus-ring regressions that static analysis missed. Human oversight helped resolve sequence synchronization in seed scripts. |
| Git/Kanban Protocol | Create branches and Issues, update the Project board, and wait for my PR/FIX/MERGE commands; never open or merge PRs on your own. | Enforcing a strict separation between code authoring and deployment commands taught me how professional teams gate production releases. Treating the LLM as a pair-programmer under strict publishing gates eliminated accidental pushes or premature merges. |
| Completion Audit | Audit the work against every acceptance criterion and planned test; report missing evidence, skipped tests and spec deviations. | Running a comprehensive audit across all acceptance criteria ensured total contract compliance. It verified that the traceability matrix reflected real test execution results without any skipped, mocked, or loosened assertions. |
